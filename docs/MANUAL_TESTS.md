# 実機での確認手順

2026-11-24時点。合成ページでの成功と、実際のpixivでの成功は分けて記録します。今の状況は[TEST_STATUS.md](TEST_STATUS.md)にあります。

自動化したブラウザ（Playwright）でpixivを開くと、Cloudflareの確認画面（HTTP 403、`cf-mitigated: challenge`）が出ます。確認画面を自動で突破することはしないので、実際の一覧での確認は、人がふつうのブラウザで行います。

## 準備

1. [README](../README.md#インストール)の手順で、開発用のChrome / Edgeのプロファイルに拡張を読み込みます。ログインが必要なら、ふつうのログイン画面から入ります。Cookieやトークンをコピーすることはしません。
2. ふつうに閲覧できる、1枚の作品と複数枚の作品を用意します。自分で描いたものか、権利の問題がないものが望ましいです。作品を投稿するか、公開範囲を変えるかは、ユーザーが決めてください。
3. DevToolsのNetworkタブを開き、`ajax/illust` と `i.pximg.net` で絞り込みます。記録するのは、ステータス、MIME、件数だけです。

## 確認すること

1. 一覧での検出
   - 対象の画面: 検索、ランキング、ユーザーの投稿、ブックマーク、フォロー新着、作品ページの関連作品。
   - 確かめること:
     - 0.25秒未満では何も取得しないこと。
     - 長くホバーしたら、その作品の `/ajax/illust/{id}/pages` だけが1回呼ばれること。
     - 一覧を素早くなぞったときは、通り過ぎたカードの多くで取得が省かれること。
     - 同じカードに戻ったら取り直さないこと。
   - Networkタブの件数を記録します。検出されないカードがあれば、DOMの構造（クラス名、画像、名前は除く）を記録します。
2. プレビューの表示
   - プレビューの画像が実際のタブで表示されること（ページの通常の `<img>` での表示）。
   - 確認する項目: 画像が縦横比どおりに表示されること、ページ数、画面からはみ出さないこと。
   - プレビューが隣のサムネイルをどれくらい隠すか（一覧をなぞる邪魔にならないか）を記録します。
   - pixivのライトとダークの両方で、暗いプレビューが浮いて見えないかを記録します。
   - サムネイルをクリックすると、ふつうにページを移ること。
3. 複数枚の作品
   - ホイールの上下、トラックパッドでの連続した操作、前後ボタン、左右キーで切り替わること。
   - 最初と最後のページで止まること。原寸を取得しないこと。
   - 1枚の作品では切り替えボタンが隠れ、ページのスクロールを邪魔しないこと。
   - GIFやうごイラのページは「このページは読めない形式です」と表示されること。
4. 生成情報を見る
   - 押したときだけ、そのページの原寸が1件、Service Worker（Initiatorが拡張）から要求されること。
   - 要求のヘッダーの `Referer` が `https://www.pixiv.net/` で、Cookieがないこと。DevToolsのService Worker用のウィンドウで確かめます。
   - 2026-11-22にService Workerからの取得を測ったときは200でした。
   - 結果のステータスとMIMEを記録します。
   - ページ側の通常の画像の要求にはルールが効いていないことも確かめます。
   - 結果が画像の横（狭い画面では下）に出て、そのとき画像が動かないこと。
   - 結果の最初の一文と目盛りが、実際の画像の内容と合っていること。
   - 押したあとはカーソルを離しても閉じず、×、Esc、外のクリックで閉じること。
5. 手元のファイル
   - pixivの作品ページで原寸を表示してブラウザで保存します。原寸を読み込めなかったときに出る「手元の画像で調べる」か、拡張機能のアイコンから開く検査ページで選びます。
   - 次の表示を、別のツール（NovelAI公式の `nai_meta.py`、ExifToolなど）の結果と比べます: プロンプト、ネガティブ、設定、ComfyUI、生データ、Stealth、EXIF。
   - 署名のデータがあっても「未検証」と表示されること。
6. 配置と操作
   - 次の場面で試します:
     - 位置: 画面の四隅、スクロール、ウィンドウのサイズ変更、狭い幅。
     - 表示: 高DPI、ライト / ダーク。
     - キー: Tab、作品リンクで↓キー、Esc。
   - カードとプレビューの両方から離れると、約200ミリ秒で閉じること。
   - Escで閉じたあと、元のリンクにフォーカスが戻ること。
   - pixivの検索欄などにフォーカスがあるときのEscが、pixiv側にも届くこと。
7. 競合と寿命
   - 次の場面で、古い画像や結果が混ざらないこと: 素早いホバー、SPAでの移動、カードの使い回し、戻る / 進む（BFCache）、2つのタブ、長時間の表示。
   - 原寸の取得は、全タブを合わせて同時に1件までであること。
   - メモリのキャッシュは、最大2分で消えること。
8. 作品ページの「生成情報」ボタン
   - 右下のボタンで、その作品が一覧と同じプレビューで開くこと。ページ送り、取り消し、失敗したときの「手元の画像で調べる」を確かめます。
   - pixivの作品ページの右下にある要素と重ならないこと。
   - URLにハッシュが付いても、検査が止まらないこと。別の作品に移ると閉じること。
9. 単独の検査ページ
   - pixivを開いていない状態で拡張機能のアイコンを押し、新しいタブで開く検査ページで次を確かめます: ファイルの選択、ドラッグ＆ドロップ、複数の画像の一覧と切り替え、取り消し、一覧を消す、コピー。
   - Networkタブに通信が出ないこと。
   - ページの外にファイルを落としても、そのファイルが開かれないこと。
10. Chrome / Edge
    - Chromeの安定版、Edgeの安定版で、1〜9の主な項目を確かめます。
    - できれば、最低バージョンの120でも確かめます。

実際のサイトで、わざと429やタイムアウトを起こさないでください（合成テストで確認済みです）。他の人の画像、プロンプト、認証情報を、リポジトリや証跡に残さないでください。

## 検出されないカードを合成fixtureにする（Issue #11）

検出されないカードがあったら、DevToolsのElementsパネルでそのカード（`li` など）を選び、Consoleで下のコードを実行します。カードの構造だけがクリップボードにコピーされます。

- 置き換えるもの:
  - 5桁以上の数字（作品IDやユーザーID）は `123` にします。
  - 画像URLの日付は、合成の値にします。
- 含めないもの: テキスト、属性の値、クラス名、画像。

中身を確かめてから `tests/thumbnail.test.ts` に加えてください。

```js
copy((function shape(node, depth = 0) {
  if (!(node instanceof Element) || depth > 10) return '';
  const tag = node.tagName.toLowerCase(), synthetic = value => value.replace(/\d{5,}/g, '123').replace(/\d{4}\/\d{2}\/\d{2}\/\d{2}\/\d{2}\/\d{2}/g, '2026/10/22/00/00/00');
  const attrs = [];
  if (tag === 'a' && node.getAttribute('href')) attrs.push(`href="${synthetic(new URL(node.href).pathname)}"`);
  if (tag === 'img') attrs.push(`src="${synthetic(node.currentSrc || node.src).replace(/^https:\/\/(?!i\.pximg\.net\/)[^/]+/, 'https://example.invalid')}"`);
  for (const name of node.getAttributeNames()) if (name.startsWith('data-') || name === 'role') attrs.push(`${name}=""`);
  const inner = [...node.children].map(child => shape(child, depth + 1)).join('');
  const open = `<${tag}${attrs.length ? ' ' + attrs.join(' ') : ''}>`;
  return tag === 'img' ? open : `${open}${inner}</${tag}>`;
})($0));
```

## pixivに投稿した後、メタデータが残るか（Issue #12）

pixivに投稿して変換されたあとも生成情報が残るかを、自分が権利を持つ画像だけで確かめます。

- 元の画像、投稿した画像、プロンプト、Cookieはリポジトリに入れません。記録するのは下の集計表だけです。
- 特定の画像が「AIで作ったか、人が描いたか」を判断するためには使いません。

手順:

1. 形式ごとに確認用の画像を用意します。
   - 形式の例: NovelAIのPNGのテキスト、NovelAIのStealth、ComfyUIのPNG、A1111 / ForgeのPNG、JPEG / WebPのEXIFなど（用意できる範囲で）。
   - ファイルごとに記録すること:
     - `sha256sum` の値。
     - 寸法。
     - 拡張の検査ページでの結果（形式、生成元の推定、Stealth、EXIF）。
2. ふつうの方法でpixivに投稿します。公開範囲は自分で決めてください。
3. 投稿したら、次の2つの方法で確かめます。
   - 拡張のホバーから「生成情報を見る」で原寸を検査し、結果とHTTPのステータスを記録します。
   - pixivの画像ビューアで原寸を開いてブラウザで保存し、ハッシュと寸法を記録して、検査ページでも確かめます。
4. ホバーで表示される縮小画像も、ブラウザで保存できれば同じように確かめます。
5. 取得できなかったもの（403、404、429など）は「メタデータなし」と混ぜず、「検査不能」として数えます。

| 形式 | サンプル数 | 生成した直後: 情報あり | 投稿後の原寸: 情報あり / なし / 検査不能 | 原寸のハッシュの一致 | 縮小画像: 情報あり / なし / 検査不能 | 備考 |
|---|---|---|---|---|---|---|
| NovelAI PNGテキスト | | | | | | |
| NovelAI Stealth | | | | | | |
| ComfyUI PNG | | | | | | |
| A1111/Forge PNG | | | | | | |
| JPEG/WebP EXIF | | | | | | |

サンプル数と、画像を選んだ条件も書いてください。少ない結果から言い過ぎないようにしてください。

## 403がどこで起きているか

| 層 | 取得するもの | 測定の結果 | 失敗したときの扱い |
|---|---|---|---|
| ページ | ふつうのpixivのページ | 自動化したブラウザでは403（Cloudflareの確認画面）、通常のHTTPでは200（11-19） | 確認画面なら自動のテストを止め、手で確かめる |
| pages API | `/ajax/illust/{id}/pages`（同じオリジンの通常のセッション） | 200（公開作品、ログアウト。11-19） | 401 / 403 / 404 / 429とpixivのメッセージを表示する。サムネイルと手元のファイルの検査は使える |
| 原寸 | APIにあるURL。拡張のService Workerから、Cookieなし、セッションルールで `Referer: https://www.pixiv.net/` を付ける | Refererなしで403（11-19）、ありで200（11-22、Service Workerから） | 失敗したら層と理由を表示し、手元のファイルの検査を案内する。取り直しはしない |
| 表示用の画像 | ページの `<img>`（ブラウザ既定のReferer） | 自動ではまだ確かめていない | 表示できなければ、作品ページへ案内する |

成功する条件は、次の3つでそれぞれ違います。

- 拡張がプレビューに画像を表示すること。
- ブラウザで原寸を開くこと。
- 拡張が原寸のデータを読むこと。

結果が違っても、根拠なしに原因を決めつけないでください。拡張自身の原寸取得にRefererを付ける以外のことはしません。次のものは使いません: ヘッダーの変更、CORSの書き換え、認証情報の持ち出し、外部のプロキシ、自動の再試行。

## コマンド（接続の確認だけ）

```bash
# ページにつながるかだけを確かめます。確認画面や拒否のときは何もせずに終わります（exit 1）。
npm run verify:live -- --url https://www.pixiv.net/ --output .verification/connectivity.json

# 自分で用意した作品の、0から数えたページを1枚だけ、作品ページのパネルで検査します。
npm run verify:live -- --url https://www.pixiv.net/artworks/ARTWORK_ID --page 0
```

使い捨てのプロファイルを新しく作って使います。ほかに指定できるオプション:

- `--headed`
- `--local-file ./your-original.png`
- `--browser msedge`（Edgeが入っている環境）

保存するもの:

- 日時、ブラウザのバージョン、gitのリビジョン、成果物のハッシュ。
- ステータスとMIME、原寸の件数、分類。

画像、プロンプト、URL、HAR、認証情報は保存しません。
