# 要件定義 — pixiv AI Metadata Inspector

更新: 2026-11-15。今回の依頼により、従来の「作品詳細ページのみ」を、閲覧中のpixiv一覧にあるユーザーが選んだサムネイルまで拡張する。実サイト受入・リリースはNO-GO。[TEST_STATUS.md](TEST_STATUS.md)

## 目的・対象

Chrome / Chromium Edge MV3で、サムネイルの拡大表示と、明示操作による表示ページのメタデータ確認を提供する。解析エンジンは既存の通常PNG対応を再利用する。画像の見た目からAI生成を判定しない。

対象画面は検索、ランキング、投稿一覧、ブックマーク、フォロー新着、関連作品など。正規pixiv作品リンク内の画像から作品IDと安全な表示用URLを識別できる場合に限る。タイトル・作者名はDOMから取得できる値だけを使い、追加APIや推測で補完しない。ユーザーが正規にアクセスできる範囲だけを扱う。

## 操作・受入条件

| ID | 要件 | 合格条件 |
|---|---|---|
| H-01 | 約250msのホバー遅延 | 短い通過では通信せず、遅延読み込みのカードにもイベント委譲で対応 |
| H-02 | フローティングプレビュー | 縦横比維持・画面内配置・ライト/ダーク・スクロール時追従、画面外の元カードは閉じる |
| H-03 | 閉じる・移動・標準操作 | パネルへ移動して継続、両方から離れて約200msで閉じる、Escapeとフォーカス復帰、元リンクを維持 |
| H-04 | 複数ページ切替 | 正確な順序、ページ/総数、前後ボタン、左右キー、閾値80px・350msクールダウン・連続ジェスチャ制御のwheel |
| H-05 | 必要なイベントだけ抑制 | 複数枚の画像領域内だけwheelを抑制。単一画像・結果内スクロール・ページ本体は通常操作 |
| H-06 | 表示と解析を分離 | 表示はAPI縮小画像/元サムネイル。原寸はMetadata/Inspectクリック時の1枚だけ |
| H-07 | ページ単位の結果 | 切替で古い結果を除去。解析済みの該当ページのみ一時キャッシュから表示 |
| H-08 | 状態を区別 | 解析中・情報あり・なし・形式未対応・取得不能・解析失敗・上限超過・取消・busyを区別 |
| H-09 | 分かる失敗説明 | APIと原寸の401/403/429を別表示。表示可能なプレビュー継続。手動ローカル読込 |
| H-10 | 安全な表示とコピー | Prompt/Negativeと主設定、グラフ/RAWの折り畳み、クリックによるPrompt/JSONコピー |
| H-11 | 旧機能維持 | 作品ページの従来パネル、ローカルファイル、キャンセル、既存パーサーの全回帰テスト |

結果の自己申告と署名の暗号学的検証を区別する。現実装はverified/invalidを生成しない。不在は非AI生成の証拠にしない。ローカルファイルを作品と同じ画像であるかのように関連付けたり、作品結果キャッシュに登録したりしない。

## 通信・権限・性能

- 一覧を走査・巡回しない。必要な作品にホバー/フォーカスしたときだけ同一オリジンのページ一覧APIを利用する。元画像URLはAPIの応答から採用し、再構築しない。
- 表示URLはHTTPSの`i.pximg.net`縮小画像パスと作品/ページを検証。解析URLは`https://i.pximg.net/img-original/img/…/{id}_p{page}.ext`だけ。
- メッセージは自拡張のpixiv top frame、tab ID、操作時の完全なタブURLを検証。取得前後に現在URLを照合し、SPA/ロード/閉じるで中止する。ページスクリプト用の橋や汎用fetchを公開しない。
- API呼出は従来パネルとhoverで共有し、タブ内で直列化。Workerの原寸取得・読込・解析は全タブで1件。自動再試行・先読みなし。429ではRetry-Afterまたは最低60秒を尊重し、その後もユーザー操作が必要。
- 一覧は24件/推定2 MiB/2分、解析結果は8件/推定8 MiB/2分のLRU。実メモリには文字列・オブジェクト管理費もある。300msの掃除で失効値を破棄。SPA・BFCache・破棄で全消去。画像バイト列をキャッシュしない。
- API JSON 1 MiB、原寸/ローカル48 MiB、通常テキスト2 MiB、40百万画素、PNG/JSONの構造・CRC・深さ・ノード数制限を維持する。通信15秒。
- 閉じたShadow DOM、textContent、最小のpixiv/pximgホスト権限。Cookie/トークンを読まない。ブラウザの通常画像表示ポリシーを使い、Referer偽装・proxy・認証やhotlink制限の回避をしない。
- 画像・Promptは端末内だけで処理し、永続保存・外部送信・追跡ライブラリを導入しない。

## 対応形式・非対象

通常PNG tEXt/zTXt/iTXt、NovelAI通常Comment（1段のenvelope）、ComfyUI prompt/workflow、A1111/Forge parametersを維持する。PNG画素の展開、NovelAI Stealth、V4/V5キャラクターcaptionの正規化、署名検証、JPEG/WebP EXIFは今回の対象外。全作品の自動解析、バッチ収集、ログイン・年齢・アクセス制限の回避も対象外。

## リリース条件

要求された6コマンド（型、単体、Chrome/Edgeビルド、ブラウザ、実MV3合成試験）が成功すること。旧テストの保証を削除せず、新しい認可・URL・競合・キャッシュ・hover/wheelの試験を加えること。

さらに実Chrome/Edge上の実pixivで、対象一覧のDOM、1/複数枚、API、原寸のHTTP状態、ログイン/公開範囲、通常画像表示とバイト取得の差、SPA・取消・コピーを確認すること。合成HTTPの成功を実pixiv成功と数えない。PASS / FAIL / NOT RUNを分ける。
