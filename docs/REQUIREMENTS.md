# 要件

2026-11-22時点。検証の状況は[TEST_STATUS.md](TEST_STATUS.md)、残りの作業は[IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md)にあります。

## 目的と範囲

Chrome と Chromium版 Edge（MV3、バージョン120以上）で、次の2つの機能を提供します。

- pixivのサムネイルのプレビュー。
- ユーザーが操作したときだけ、表示中のページのメタデータを確認する機能。

画像の見た目からAI生成かどうかを判定することはしません。

対象の画面:

- 検索、ランキング。
- ユーザーの投稿、ブックマーク、フォロー新着。
- 作品ページ（関連作品とパネル）。

条件:

- 作品リンク（またはそのすぐ近くのカード）の中の画像から、作品IDと安全な表示用URLを特定できる場合に限ります。
- タイトルと作者名は、DOMから取れる値だけを使います。
- 扱うのは、ユーザーが普通にアクセスできる範囲だけです。

## 操作の受け入れ条件

| ID | 要件 | 合格条件 |
|---|---|---|
| H-01 | 約250msのホバー遅延 | さっと通り過ぎただけでは通信しない。なぞっている間は一覧の取得をさらに150ms待ち、離れたカードでは取得しない。あとから読み込まれるカードにも、イベント委譲で対応する |
| H-02 | フローティングプレビュー | 縦横比を保ち、画面内に収め、ライト / ダークに対応し、スクロールに追従する。カードが画面外に出たり消えたりしたら閉じる |
| H-03 | 閉じ方・移動・元の操作 | プレビューへ移っても開いたまま。カードとプレビューの両方から離れて約200msで閉じる。Escで閉じ、フォーカスを戻す。元のリンクはふつうに動く |
| H-04 | 複数ページの切り替え | 順序が正しい。「ページ / 総数」の表示、前後ボタン、左右キー、ホイール（80pxでしきい値、350msのクールダウン、連続した操作で1ページ） |
| H-05 | 止めるイベントは必要なものだけ | 止めるのは、複数枚の作品の画像の上でのホイールだけ。1枚の作品、結果欄のスクロール、ページ本体はふつうに動く。フォーカスが拡張の外にあれば、Escはページにも届く |
| H-06 | 表示と解析を分ける | 表示にはAPIの縮小画像か元のサムネイルを使う。原寸はMetadata / 検査ボタンを押したときに1枚だけ取る |
| H-07 | ページごとの結果 | ページを切り替えたら古い結果を消す。一時キャッシュから出すのは、解析済みのページだけ |
| H-08 | 状態を見分けられる | 解析中、情報あり、なし、未対応の形式、取得できない、解析の失敗、上限超え、取り消し、処理中を区別する |
| H-09 | 失敗の理由がわかる | APIと原寸それぞれの401 / 403 / 404 / 429 / 5xx / タイムアウトを、どこで起きたかと合わせて表示する。プレビューはそのまま使える。手元のファイルで調べる方法を案内する |
| H-10 | 安全な表示とコピー | プロンプト、ネガティブ、主な設定を表示。グラフと生データは折りたたむ。コピーはボタンを押したときだけ |
| H-11 | 既存の機能を残す | 作品ページのパネル、手元のファイル、取り消し、既存の解析の回帰テスト |
| H-12 | 検査できないページ | 原寸URLが対応外の形式なら、ページ番号を保ったままプレビューだけにし、検査ボタンは無効にする |

## メタデータの受け入れ条件

| ID | 形式 | 合格条件 |
|---|---|---|
| M-01 | PNGのtEXt / zTXt / iTXt | 構造、CRC、上限、文字コード、重複したキーの扱いを保つ |
| M-02 | NovelAI（PNGのテキスト） | Softwareの自己申告に加えて、Description / Source / Comment、1段のComment envelope、V4 / V4.5のキャラクター別プロンプト（公式APIの形式に合う場合だけ） |
| M-03 | NovelAIのStealth形式 | 公式の書き込み・読み取り処理と同じ結果（`stealth_pngcomp`）。対応していない画像の形は「未検査」、アルファがなければ「なし」 |
| M-04 | ComfyUI | prompt / workflowのJSONを省略せず、折りたたんで表示する。モデルやプロンプトは推測しない（PNGのテキストとWebPのEXIF） |
| M-05 | AUTOMATIC1111 / Forge | parameters（PNG）とUserComment（JPEG / WebP）。引用符の中のカンマでは区切らない |
| M-06 | 判定の意味 | 「メタデータから推定」と示す。署名は未検証と表示し、検証済みにはしない。情報がない・未対応・取得できないことを、AI生成でない根拠にしない |

## 通信・権限・性能

### 取得するURL

- 一覧を走査したり巡回したりしません。使うのは、ホバーまたはフォーカスした作品のページ一覧APIだけです。
- 原寸URLはAPIの応答にあるものを使い、自分で組み立てません。
- 表示用のURLは、HTTPSの `i.pximg.net` の縮小画像のパスであることと、作品とページが合うことを確かめます。
- 解析に使うURLは `https://i.pximg.net/img-original/img/…/{id}_p{page}.{png|jpg|jpeg|webp}` だけです。

### メッセージの照合

- 取得の前後に、次の項目を照らし合わせます。
  - この拡張の、pixivのトップフレームからのメッセージであること。
  - タブID。
  - 作品ID（作品ページのパネルの場合）、または操作したときのURLそのもの（プレビューの場合）。
- ページのスクリプトとのつなぎや、なんでも取得できるfetchは公開しません。

### 原寸の取得

- Service Workerから `credentials: 'omit'`、`redirect: 'error'` で取得します。
- 全タブで同時に1件までです。自動の再試行と先読みはしません。
- i.pximg.netが求める `Referer: https://www.pixiv.net/` だけを、セッションルールで付けます（2026-11-22のメンテナーの決定、Issue #9）。
  - ルールの対象: この拡張が始めた、タブに属さない、GETの、`img-original` への要求に限ります。
  - 変えないもの: レスポンスのヘッダー、他のサイトやpixivのページの通信。
- 429では、`Retry-After`（最低60秒）をService Workerとタブの両方で守ります。
- 失敗したときは、理由の説明と、手元のファイルで調べる方法を示します。

### キャッシュと上限

- キャッシュは、タブのメモリの中のLRUです。
  - ページ一覧: 24件、推定2 MiB、2分。
  - 結果: 8件、推定8 MiB、2分。
- 画像のデータはキャッシュしません。SPAでの移動、BFCache、終了時にすべて消します。
- 上限:
  - APIのJSON: 1 MiB。
  - 原寸と手元のファイル: 48 MiB。
  - テキスト: 2 MiB。
  - 画素数: 4,000万。
  - Stealth形式: 圧縮1 MiB、1行1 MiB。
  - 通信: 15秒。

### 表示と権限

- closedのShadow DOMの中に置き、`textContent` で表示します。
- ホスト権限はpixivとpximgだけです。API権限は、上のRefererのための `declarativeNetRequestWithHostAccess` だけです。
- Cookieやトークンは読みません。
- 画像とプロンプトは端末の中だけで処理します。保存、外部への送信、追跡のためのライブラリは入れません。

## やらないこと

- すべての作品の自動解析、まとめての収集や一括ダウンロード。
- ログイン、年齢制限、アクセス制限、レート制限の回避。
- 上のReferer以外のヘッダーの変更、CORSのレスポンスの書き換え。
- 外部のプロキシ。
- 画像の見た目によるAI判定。
- 署名の検証なしでの「本物」の判定。
